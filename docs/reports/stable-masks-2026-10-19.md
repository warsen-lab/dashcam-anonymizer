# 打码观感与速度：校准与验收（2026-10-19 设计，2026-10-20 验收）

设计：`docs/superpowers/specs/2026-10-19-stable-masks-and-speed-design.md`（§3.6–§3.8 是验收中补充的三条）；计划：`docs/superpowers/plans/2026-10-19-stable-masks-and-speed.md`。原始结果：`data/reports/calib/results.jsonl`、`data/reports/calib/ghost_exp.jsonl`、`data/reports/stable-3seg/`、`data/reports/stable-full/`。

本机 Apple Silicon Mac，Release 构建，r3 学生模型 + YuNet，两者都在 CoreML 上、每个关键帧并行跑。

## 结论

- **验收十项全部通过**（下表），观感大幅改善：全片帧间跳变 20% → 1.0%，每帧打码面积 p99 25% → 6.4%、最大 79% → 15.4%；10 档 219 fps。
- **代价：关键帧之间的覆盖下降。** 验收用的参照帧每 48 帧一张，10 档每 6 帧一个关键帧，所以参照帧全是关键帧，召回验收量不到补框。改用逐帧检测作参照：高分目标在关键帧之间仍有约 99% 被盖住；中分人脸 97% → 84%，中分车牌 99.5% → 94%（见"关键帧之间的覆盖"）。
- 验收中做了三处补充（用户逐条确认）：大人脸要更高分（§3.6）、低分配对只走严格的第一轮（§3.8）、`hold_lost_ghosts` 对比实验（§3.7，结论是默认关）。

- **A（收缩）：** 四个值都没有满足面积 p99 ≤ 10%，按规则取 p99 最小的 S = 0.2，记"A 阶段没有满足面积上限的值"。收缩速度几乎不影响跳变。
- **B（确认门槛）：** 对召回、面积、跳变的影响都在噪声内；按规则取召回达标的最大值 F = 0.5、P = 0.2。
- **C（外扩）：** 跳变的主要来源是运动外扩：M 从 0.5 降到 0.25，跳变从约 10% 降到 4% 左右，面积最大值从 22% 降到 11–12%。按规则（召回达标且跳变 ≤ 5% 里 p99 最小）取 E = 0.2、M = 0.25。
- 所有行的同轨多框帧都是 0；检测墙钟时间约等于较慢的学生模型，不是两者之和（并行生效）。

选定：shrink_per_frame = 0.2，face_confirm_score = 0.5，plate_confirm_score = 0.2，expand_fraction = 0.2，motion_expand_fraction = 0.25。

## 验收中的补充

第一次全片验收（只用上面的选定值）面积最大值 40.9%，不过；三段四项通过。按计划停下，逐条交给用户决定：

1. **大人脸要更高分（§3.6，用户选定）。** 超过 30% 的 64 帧（12 段）都是 YuNet 把路面、楼群、隧道墙认成大脸：全片 81 个超过画面 5% 的人脸框全来自 YuNet，分数 0.30–0.58（中位数 0.33）。规则：人脸框超过画面 5% 且分数 < 0.6 的直接丢弃。全片丢 81 个，超过 30% 的帧降到 15 帧，最大值 39.2%，仍不过。
2. **低分配对只走严格的第一轮（§3.8，用户选定）。** 剩下的 15 帧出在第 20862–20874 帧：一条 0.33 分的 YuNet 人脸轨迹被宽松的第二轮配上了画面另一角的 0.31 分人脸，插值框斜穿画面。规则：配对任一端低于本类确认门槛，就只能在第一轮配。
3. **`hold_lost_ghosts` 对比实验（§3.7，用户选定先做实验）。** 两段校准视频，开 / 关：

   | | 关 | 开 |
   |---|---|---|
   | 时间覆盖 人脸 / 车牌 | 83.4% / 93.0% | 83.7% / 93.1% |
   | 中分人脸（0.5–0.8） | 90.4% | 90.6% |
   | 面积 p99 / 框数 p95 | 7.05% / 54 | 7.53% / 58 |
   | 跳变 | 3.87% | 3.87% |

   收益只有 0.1–0.3 个百分点，面积却变大：关键帧之间的漏遮主要不是"短暂漏一两次"，所以默认保持关。

## 关键帧之间的覆盖

参照帧全是关键帧，所以另用 `--detect-every-frame` 的逐帧检测（只算确认过的、够大的框）作参照，看稀疏打码在每一帧盖住了多少（≥ 80% 面积算盖住）。两段校准视频合计、同一份逐帧参照：

| 分数段 | 旧设计（上一轮） | 新设计 + 旧参数 | 新设计 + 标定值 | 最终（再加 §3.8） |
|---|---|---|---|---|
| 人脸 ≥ 0.8 | 100% | 99.7% | 99.1% | 98.6% |
| 人脸 0.5–0.8 | 97.3% | 93.2% | 90.4% | 83.7% |
| 人脸 < 0.5 | 94.8% | 85.0% | 81.6% | 72.2% |
| 车牌 ≥ 0.5 | 100% | 99.9% | 99.8% | 99.8% |
| 车牌 0.2–0.5 | 99.5% | 98.6% | 96.9% | 94.0% |
| 车牌 < 0.2 | 97.6% | 93.7% | 88.0% | 82.1% |

（"最终"一列的逐帧参照是带 §3.6 规则重跑的，和前几列的参照差别只在 81 个被丢的大脸，不影响这几段的结论。）

- **下降来自哪里**（标定值、§3.8 之前，中分人脸 552 个漏遮）：64% 附近根本没有打码框；按位置分，62% 附近一个间隔内都没有轨迹（逐帧检测看得到、关键帧上没检到，任何补框都救不回，只有提高档位有用），32% 在轨迹第一次被检出之前的一个间隔里（删掉"新目标往前补一个间隔"的代价），6% 在轨迹结束之后。中分车牌 350 个：49% 在轨迹开始之前、35% 附近没有轨迹、15% 在结束之后。
- **§3.8 的代价：** 同一个目标的分数在门槛上下波动时，配对的一端落到门槛以下就只能走第一轮，移动快的目标会断成两条轨迹，断开处要重新确认。中分人脸因此从 90.4% 降到 83.7%。
- **"检到、漏、漏、检到"的空档**（`data/calib/gaps.py`，新轨迹在旧轨迹最后一帧之后恰好 1 或 2 个间隔出现在附近）：最终版本每段 1581–2141 次（1 个间隔 992–1337 次、2 个间隔 589–804 次），大部分是车牌；它们覆盖了逐帧参照里 4183 / 5988 / 4382 个漏遮（三段的时间漏遮分别是 7755 / 11547 / 8030）。标定值、§3.8 之前这一数字是 445–600 次（只数 2 个间隔）。

## 已知问题

- **关键帧之间的中低分目标覆盖下降**（见上节）。若要找回一部分，可选的方向：对高分新目标恢复"往前补一个间隔"（约能找回中分漏遮的三分之一，代价是新出现的码提前 0.1 秒出现）；或提高 `detect_fps`。
- **一排停着的车被打成横向长条**：第 2700 秒右侧一排停车的车牌框连成一条约 420 × 120 px 的马赛克。
- **§3.8 让低分目标的轨迹更容易断**：断开处要重新确认，连续两次检测都是低分的快速目标可能整段不打码。
- **验收参照的盲区**：参照帧都在关键帧上，召回数字只代表检测帧。以后改补框，要同时看本报告"关键帧之间的覆盖"一节的逐帧参照。
