# 代理验证第三轮：r3 + YuNet 人脸检测器（2026-10-19）

接 `docs/reports/proxy-validation-2026-10-19-r3.md`。原始结果：`data/reports/r3-3seg/`（只用 r3）、`data/reports/r3-yunet-3seg/`（r3 + YuNet）。

## 为什么加 YuNet

上一轮 r3 漏掉的 3 张真人脸（戴护目镜的工人、灌木后的两张小脸），r3 给它们的最高分只有 0.002–0.009。要靠压低阈值盖住它们，几乎得把阈值降到 0。

老师标注用的人脸模型之一 YuNet（OpenCV Zoo，MIT 许可证，230 KB）以 0.68–0.75 分检出了它们。所以把 YuNet 作为第二个检测器接进 `vc_redact`：

- 车牌仍由 r3 负责；人脸取两个检测器的并集（同类且 IoU ≥ 0.5 的框合成并集框，其余原样保留），结果只会比单个检测器多打。
- YuNet 阈值事先定为 0.3，取老师"低置信人脸"区间的下限，没有在留出段上调。
- 用法：`vc_redact --model data/models/r3 --face-model data/models/yunet`。人脸模型用 `python -m vc_train yunet --out data/models/yunet` 从缓存的 OpenCV Zoo 文件生成。

实现经过三份独立审查（C++、Python、整体），都没有严重或重要问题。

- **解码一致：** 和 OpenCV `FaceDetectorYN` 逐框一致，误差 ≤ 0.1 px。
- **CoreML 与 CPU 一致：** 分数完全相同。CoreML 每帧 8.9 ms，CPU 28.5 ms。

## 结果（三段留出视频，选定配置 10 fps）

留出段是 1200s、2400s（上一轮新留出段），加上从没用过的确认段 60s（原片 60–180 秒）。

| 指标 | 只用 r3 | r3 + YuNet |
|---|---|---|
| 高置信人脸 | 40/48 = 83.3% | **48/48 = 100%**（95% 区间 92.6–100%） |
| 低置信人脸 | 87/188 = 46.3% | **171/188 = 91.0%** |
| 高置信车牌（代理规则） | 766/805 = 95.2% | 766/805 = 95.2% |
| 低置信车牌 | 73.5% | 73.7% |
| 误打面积均值 | 2.4–3.3% | 3.0–4.2% |
| 速度（机器有其他负载，只作范围） | 139–210 fps | 82–158 fps；空闲时实测 144 fps |
| 输出完整性 | 全部通过 | 全部通过 |

各段明细（r3 + YuNet）：

- 1200s：人脸 10/10，车牌 408/440；
- 2400s：人脸 24/24，车牌 76/76；
- 60s（确认段）：人脸 14/14（只用 r3 时 10/14），车牌 282/289。

## 车牌漏遮逐个核查

代理规则下还有 39 个车牌漏遮，人眼核查：

| 来源 | 个数 | 是什么 |
|---|---|---|
| 1200s | 29 | 等红灯时停在画面右下角的公交尾灯（老师误检） |
| 1200s | 2 | 水马上的字、公交线路号 LED 屏（老师误检） |
| 1200s | 1 | 公交车侧面的小标识，难判断是不是车牌 |
| 60s | 6 | 货车的"SLOW VEHICLE"警示牌 ×3、TOYOTA 字样旁的 L 牌、车顶文字条、公交车身彩绘（老师误检）；旁边真正的车牌都已盖住 |
| 60s | 1 | **真车牌**：迎面公交车的前牌，28×10 px |

- **校正后车牌是 766/768 ≈ 99.7%。** 计算方法是去掉 37 个参照误检，剩下的 2 个漏遮按漏检算。这和上一轮一样只核查了漏遮一侧，结论偏乐观。
- **这 2 个靠调阈值盖不住。** 阈值压到 0.001，r3 在这两处也没有任何框，只能靠更多同类训练数据（公交、货车上的小车牌）解决。

## 代价与已知问题

- **误打变多。** 误打面积均值多了约 0.6–0.9 个百分点。YuNet 独有的框分数中位数只有 0.38，里面有不少不是人脸。
- **个别帧误打面积很大。** 例如 2400s 有一帧达到 55%：两个 YuNet 误检被补框逻辑的宽松配对连成一个"快速目标"，打码区域扫得很宽。审查认为不该收紧：YuNet 补回的正是小人脸，它们快速移动时就靠这种配对插值。这是按"宁可多打"规则的取舍。
- **速度下降约 20%**（空闲时从约 175 fps 降到约 144 fps），仍是实时的 2 倍多。两个检测器目前串行运行，改成并行可以收回一部分。
- **人脸样本仍然偏少。** 三段合计 48 个高置信人脸，即使 48/48，区间下限也只有 92.6%，证明不了 99%。

## 结论

- **人脸：** 加 YuNet 后，三段留出视频上高置信人脸全部盖住，低置信人脸从 46% 提高到 91%，从没用过的确认段也是 14/14。"漏打人脸"这个问题在现有数据上已经解决；但样本量证明不了 99%，需要行人更多的视频来证明。
- **车牌：** 校正后约 99.7%，剩 2 块公交上的小车牌没盖住。
- **按代理规则自动判定，P1 仍不通过。** 原因是老师参照里的误检，一个停着的尾灯就占了 29 个漏遮。严格验收需要人工金标准。
- **推荐用法：** `vc_redact --model data/models/r3 --face-model data/models/yunet`，配合 `configs/redact.json` 的默认值。
