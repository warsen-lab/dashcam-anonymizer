# 减少误打：复核模型与重训学生模型

日期：2026-10-21。前置：`docs/superpowers/specs/2026-10-19-stable-masks-and-speed-design.md`（打码流水线与验收口径）、`docs/reports/stable-masks-2026-10-19.md`（当前默认设置的验收结果）。回退点：tag `pre-fp-filter-2026-10-21`（`e36394b`）。

## 1. 背景与目标

马赛克大小已经可以接受（车牌只打在框内、恒定画质编码），用户希望**误打再少一些**。

### 摸底（三个留出段，r3 + YuNet，10 档，只看参照帧）

口径：打了码的检测框，在同一参照帧上与任何同类老师框（含最低分的）IoU 都 < 0.1，记为"对不上老师框"。脚本与抽样拼图在 `data/reports/false-positives/`（不进仓库）。

| 类别 | 打码的框 | 对不上老师框 | 主要来源 |
|---|---|---|---|
| 车牌 | 8,379 | 4,588（55%） | 分数 < 0.2 的 3,664 个；0.2–0.5 的 855 个；≥ 0.5 的 69 个 |
| 人脸 | 872 | 641（74%） | 只有 YuNet 437 个；只有学生模型 164 个；两者都检出 40 个 |

抽样 160 张看图：
- **车牌**：多数是尾灯、后视镜、车轮、蓝色箭头路牌、绿色路名牌、排水格栅，约两成是老师漏标的远处小车牌。
- **只有 YuNet 的人脸**：几乎全是红色箭头信号灯，其余是让行标志、树、尾灯。
- **只有学生模型的人脸**：多是车轮和暗处的窗户，少数是真人。
- **两个检测器都检出、分数 ≥ 0.5 的人脸**：基本可靠。

**只调门槛不行**：车牌门槛 0.05 → 0.1 能去掉一半误打，但老师高分（≥ 0.5）车牌漏掉约 5%；YuNet 门槛 0.3 → 0.4 能去掉约 64% 的 YuNet 误打，但漏掉约 8% 的真人脸。

### 根因

- **学生模型**：训练标签直接来自老师。OWLv2 的门槛是 0.1，尾灯、路牌这类老师低分误检进了标签。
- **YuNet**：现成的预训练模型，不能重新训练，只能在它后面加一道关。

### 用户已定的取舍

- **召回线不动**：人脸 ≥ 95%、车牌 ≥ 98%，只接受不伤召回的改法。
- **判定交给模型**：本地用老师模型复看，拿不准的才给人；测试期可以接 Codex 这类多模态 LLM。先只试判 100 张。
- **复核模型要轻量。**
- **两种方案都做**：A 复核模型 + B 重训学生模型。
- **线上抽检另起子项目**：随机抽检、可配置的多模态 LLM 判定、每天抽检上限、启停开关、自动再训练，等本设计验收后再单独设计。本设计的判定接口和记录格式要能被它直接复用。

## 2. 总体流程与数据划分

- **挖反例、训练**：只用 r3 的 10 个训练段，即 `sg_drive_300s`、`600s`、`900s`、`1500s`、`1800s`、`2100s`、`2700s`、`3000s`、`3300s`、`3600s`。
- **验收**：只用三个留出段 `sg_drive_1200s`、`2400s`、`60s`。
- **不用 `sg_full.mp4`**：它包含留出段的画面。

步骤与交付顺序：

1. **挖候选**（§3.2）。
2. **判定**（§3.3），先试判 100 张（§3.4），用户核对、过关后再放量。
3. **复核模型 v1**（§4），单独验收（§6）、单独合并。
4. **重训学生模型 r4**（§5），单独验收；r4 上线后复核模型重训为 v2。

3 不等 4。

## 3. 候选与判定

### 3.1 "没把握的框"

只有这些框会被挖成候选、在运行时被复核；其余框照旧打码。

- **车牌**：分数 < `verify_plate_below`（默认 0.5）。
- **人脸**：只有一个检测器检出（`src` 为 `student` 或 `yunet`），或分数 < `verify_face_unless_both_above`（默认 0.5）。即两个检测器都检出（`student+yunet`）、分数也不低于这个值的人脸不复核。

### 3.2 挖候选：`vc_hardneg mine`

新 Python 包 `py/vc_hardneg`（命令 `python -m vc_hardneg`）。

- **输入**：`vc_redact` 用当前默认设置跑训练段的输出（`detections.jsonl`、`masks.jsonl`）和原视频。只取打了码的框，即 `confirmed` 不为 false。
- **去重**：用 `masks.jsonl` 里同一关键帧的 `detected` 框按中心对上轨迹号，同一条轨迹最多取 3 张，在轨迹上均匀取。
- **小图**：以框为中心的正方形，边长取框长边的 2.5 倍、不小于 32 px，超出画面的部分用灰色（114）填充。以原分辨率存 PNG。
- **清单**：`candidates.jsonl`，每张一行，字段 `id`（段 + 帧 + 轨迹 + 类别的稳定散列）、`video`、`frame`、`cls`、`box`（整帧坐标）、`crop_box`（小图在整帧中的位置）、`score`、`src`、`track`、`image`（相对路径）、`frame_teacher`（整帧老师对照：与该框 IoU ≥ 0.3 的同类老师框的最高分，没有则为 0）。

- **补充（写实施计划时细化）**：
  - 复核模型的训练小图由 `vc_redact --dump-verify-crops` 直接转储（`verify_crops.bin` + `verify_crops.jsonl`，即运行时的 64×64 RGB 输入），保证训练与运行时像素一致；`candidates.jsonl` 因此多记 `dump_dir`、`dump_index`、`crop_origin`。
  - 只在有老师标注的帧上挖候选，转储取每 48 帧一次（`--dump-verify-every 48`）。原分辨率小图只用于判定和人工复核。

### 3.3 判定：`vc_hardneg judge`

**接口**：输入一张候选（小图 + 框在小图中的位置 + 类别），输出一条 `judgment`。

```json
{"id": "...", "verdict": "yes|no|unsure", "judge": "frame_teacher|teacher|llm:<名字>|human", "score": 0.0, "detail": "..."}
```

所有判定追加写入 `judgments.jsonl`。同一 `id` 以最后一条为准，人工判定优先于模型。线上抽检子项目复用这个格式。

**依次执行的裁判**

1. **整帧老师**：`frame_teacher ≥ 0.5`，直接判 `yes`。
2. **本地老师复看**（默认）：小图放大 4 倍，车牌用 OWLv2，人脸用 RetinaFace；YuNet 是误打来源之一，不当裁判。
   - `yes`：放大后在原框位置检出（IoU ≥ 0.3），且分数 ≥ 0.3（人脸 0.7）。
   - `no`：放大后连分数 ≥ 0.1（人脸 0.3）的框都没有。
   - 其余为 `unsure`。
   - 这些门槛是初值，由 §3.4 的试判校准，写进 `vc_hardneg` 的配置文件。
3. **多模态 LLM**（可选，默认关闭）：调用一个可配置的外部命令（命令模板、提示词、超时写在配置文件里），传入小图路径和类别，读回 `{"verdict": ..., "reason": ...}`。只复判 `unsure`，或在试判时与本地老师并列对比。
   - 会把车牌、人脸小图发到外部服务，所以**缺省拒跑**：只有设置了 `VC_HARDNEG_ALLOW_LLM=1` 才执行，每次运行先打印将发送的张数。
   - 超时、返回不是合法 JSON，一律判 `unsure`。
   - 测试期接 Codex：本机目前没有 `codex` 命令行，接入时由用户提供调用方式。
4. **人工**：仍为 `unsure` 的，`vc_hardneg review` 生成一个本地小图墙网页（只读本地文件、不联网），点击标"是 / 不是"，导出 JSON，`judge --import` 读回。

### 3.4 100 张试判（放量前的关卡）

- **抽样**：按四类分层，各 25 张，固定随机种子：车牌 < 0.2、车牌 0.2–0.5、只有 YuNet 的人脸、只有学生模型的人脸。
- **判定**：本地老师判一遍；LLM 若已启用也判一遍。
- **核对**：生成核对网页，每张小图旁显示各裁判的结论，用户逐张标真值。
- **关卡**：判 `no` 的小图里，真车牌、真人脸不超过 2%。不过关就调整 §3.3 的门槛、把边界情况推给 `unsure` 后再试；过关才放量判定全部候选。
- **记录**：结果（各裁判与真值的混淆矩阵、选定的门槛）写进报告。

## 4. 复核模型（方案 A）

### 4.1 模型与训练

- **输入**：§3.2 的小图，缩放到 64×64 RGB，取值 0–1。
- **输出**：两个 logit，分别表示"是真人脸"和"是真车牌"，按框的类别取对应的那个，过 sigmoid。
- **结构**：小 CNN，约 0.3M 参数，从零训练。精度不够时，先征得用户同意再下载 MobileNetV3-Small 的 ImageNet 预训练权重（约 10 MB）。
- **数据**：判定为 `yes` / `no` 的候选（`unsure` 不用）。10 个训练段按段切 8 / 2 作训练 / 验证，验证段在 `model.json` 里记录。
- **代码**：`py/vc_train/verifier.py`，`python -m vc_train verifier ...`，在本机 MPS 上训练。
- **导出**：`data/models/verifier-v1/model.onnx` 和 `model.json`，`model.json` 包含：
  - `kind: "verifier"`、`classes`（`["face", "plate"]`）、`input`（64×64、RGB、scale）、`crop_factor`（2.5）、`min_crop_px`（32）、`pad_value`（114）；
  - 每类放行门槛 `pass_threshold`；
  - 训练清单与判定文件的 sha256，验证集的指标。

### 4.2 放行门槛

每一类在验证集中判为 `yes` 的小图里，至少 99.5% 要被放行，取满足这个条件的最大门槛。之后以 §6 的召回验收为准。

### 4.3 接入 `vc_redact`

- **新单元** `cpp/src/detect/verifier.{h,cpp}`：
  - 读 `model.json` 和 `model.onnx`，与检测器共用执行后端：本机 CoreML，Linux 走 `--ep` 选的后端。
  - 输入一帧和一组框，按 §3.2 的规则从解码帧（YUV）裁小图，双线性缩放到 64×64，转 RGB；一个关键帧上的框凑成一批推理，返回每个框的放行分数。
  - 裁图与转换写成纯函数，单独测试。
- **位置**：`redact_job` 中，检测与大人脸规则（2026-10-19 设计 §3.6）之后、`BoxTimeline` 之前。只复核本文 §3.1 的框；放行分数 < 门槛的框不交给 `BoxTimeline`，所以不打码、不保持、不留幽灵框，也不参与低分确认（2026-10-19 设计 §3.4）。
- **记录**：
  - `detections.jsonl`：被复核的框加 `verify`（放行分数，保留 4 位）；被拦下的加 `"verified": false`，并照写 `confirmed: false`。
  - `stats.json`：`verifier`（模型目录名），`verify` 节记录复核框数、拦下框数（按类别）、批次数和耗时（与 `stages` 同口径）。
- **开关**：
  - 新参数 `--verifier-model <dir>`。不给时行为与现在完全一致（回退靠这一点）。
  - `scripts/redact.sh` 读 `VC_VERIFIER`：默认 `data/models/verifier-v1`，设为空则不复核。
- **配置**（`configs/redact.json`）：
  - `verify_plate_below`（默认 0.5）、`verify_face_unless_both_above`（默认 0.5），取值 [0, 1]；
  - `verify_threshold_face`、`verify_threshold_plate`：可选，覆盖 `model.json` 里的门槛；不写则用模型的。
- **出错**：给了 `--verifier-model`，但目录缺文件、`model.json` 不合法、`kind` 不是 `verifier`、或 ONNX 的输入输出形状与 `model.json` 不符，启动时报错退出，不悄悄跳过复核。
- **速度**：每个关键帧通常几到几十个候选，预计每个关键帧多 1–2 ms；以 §6 实测为准。

## 5. 重训学生模型（方案 B）

> **2026-10-21 补充**：方案 A 已停用（复核模型在任何有效门槛下都会拦掉真车牌，详见 `docs/superpowers/plans/2026-10-21-false-positive-filter-retrain.md` 的"背景"）。方案 B 的实施有两处细化：反例样本以误检为中心裁 640×640、保留区域内其余清洗后的标签，而不是无标签的背景图；低分标签先抽 1,000 个判定、人工抽核 100 个，再由用户在三种清洗策略里选。§5.4（r4 之后重训复核模型）暂不执行。

### 5.1 洗标签

- **对象**：训练段里老师的低分框，即配置里 `plate_low_score`（0.1–0.3）、`face_low_score`（0.3–0.5）那一档。用 §3.3 的判定接口与 §3.4 的关卡，生成 `label_judgments.jsonl`。
- **处理**：判 `no` 的从训练标签里去掉；`unsure` 的保留。
- **不改原件**：`data/labels/<段>/yolo/` 保持不变。`vc_train` 建数据集时新增参数 `--label-judgments <file>`，跳过被判 `no` 的框，被跳过的框数写进数据集清单。

### 5.2 加反例

- **来源**：§3.2 挖出、判为 `no` 的学生误检。
- **方式**：以 `vc_train` 现有的原尺度裁图方式，作为没有标签的背景图加入训练集。
- **数量**：背景图约占数据集的 10%，按类别和分数段（车牌 < 0.2、0.2–0.5；人脸按来源）均衡抽样，同一条轨迹最多 3 张。比例写进数据集清单。

### 5.3 训练 r4

- **配方**：从 r3 的权重继续训练，配方同 r3（1920×1088，按时间预算），只用 10 个训练段。
- **执行**：训练会占用本机几个小时。开始前告知用户，放在后台运行，期间不跑其他重任务。
- **产出**：`data/models/r4/`。`model.json` 记录训练清单的 sha256，以及用到的判定文件。

### 5.4 r4 之后

- 用 r4 重新挖候选；已判定过的 `id` 复用旧结论，只判新出现的。
- 复核模型重训为 v2，重新定放行门槛。
- r4 替换 r3 的条件：按 §6 比较"r3 + 复核"与"r4 + 复核"，召回不降且误打更少才把默认模型换成 r4；否则保留 r3，数据留到下一轮。

## 6. 验收

**基线**：同一台机器、同一时段，用现在的默认设置（r3 + YuNet，10 档，不复核）跑三个留出段。

**召回（硬门槛，不过不上线）**
- 排除表沿用现有的，三段合计：人脸 ≥ 95%，车牌 ≥ 98%。
- **不许新漏**：基线遮住、新版没遮住的参照框，逐个裁图核查。只要有一个是真车牌或真人脸，就算不过，回去调门槛或 §3.1 的范围。
- **关键帧之间**：用 `--detect-every-frame` 的逐帧参照，按 2026-10-19 报告的分数段统计覆盖，每段比基线低不超过 1 个百分点。

**误打（目标，未达到也出报告，由用户决定是否上线）**
- 对不上老师框的打码（§1 的口径）：人脸至少减少 50%，车牌至少减少 30%。
- 一并报告误打面积、屏上面积均值 / p99、帧间跳变。屏上面积 p99 ≤ 10%、帧间跳变 ≤ 5% 仍须满足。

**速度**：10 档在 `sg_drive_2400s` 上的吞吐，比同时段基线慢不超过 10%。

**组合**：r3、r3 + 复核、r4、r4 + 复核。

**报告**：写进 `docs/reports/`，附被拦下框和仍然误打的框的抽样拼图。

## 7. 测试

本机只跑与改动相关的测试文件，全量交给 CI。

- **Python（pytest）**：
  - 挖候选：轨迹去重、裁图边界与填充、清单字段；
  - 判定：用假裁判测试裁判顺序、"最后一条为准"、人工优先；LLM 缺省拒跑、超时与非法 JSON 判 `unsure`；
  - 100 张抽样的分层与关卡计算；
  - 数据集读入判定文件后跳过被判 `no` 的框、背景图比例；
  - 复核模型训练、导出 ONNX、`model.json` 字段的冒烟测试（几步、极小数据）。
- **C++（GoogleTest）**：
  - 仿照 `cpp/tests/data/make_const_yolo.py`，生成一个输出常量的复核模型夹具；
  - 裁图与 YUV → RGB 缩放的纯函数，§3.1 的范围判断，批量推理；
  - `redact_job`：被拦下的框不打码，`detections.jsonl` 的 `verify` / `verified` 字段，不给模型时输出与现在一致；
  - 配置解析与 `model.json` 校验的出错路径。

## 8. 不在本设计范围内

- 线上随机抽检、可配置的多模态 LLM 抽检、每天抽检上限、启停开关、自动再训练与模型晋级：第 2 个子项目，本设计验收后单独设计。
- 改动 YuNet 本身或换掉人脸检测器。
- 车牌、人脸以外的类别。
