# 99.9% 测试集与按目标指标（子项目 1）

日期：2026-10-22。前置：`docs/superpowers/specs/2026-10-21-false-positive-filter-design.md`（误打设计，vc_hardneg 判定器）、PR warsen-lab/dashcam-anonymizer#3（默认 r3 + `plate_min_width_px` 16）。

## 1. 背景与目标

用户希望车牌和人脸都做到 99.9%。现在的水平（三个留出段，r3 + 16 px，按帧、对老师参照）：
- 车牌召回 98.2%（754 / 768）；
- 人脸召回 100%（47 / 47），但 95% 区间下限只有 92.4%。

现在测不出 99.9%，原因有两个：
- **样本太少**：要在统计上证明 ≥ 99.9%，即使一个不漏也需要约 3,000 个目标。
- **参照不可靠**：参照来自老师模型，老师自己的错误率远高于 0.1%。

### 用户已定的口径

- **主指标：按目标、看得清的不泄露率 ≥ 99.9%**，车牌、人脸各算各的。
  - 以每辆车的车牌、每个人的脸为一个目标。
  - 只要有一帧"看得清"却没被打码，这个目标就算泄露。
- **看得清**：暂停并放大原画面能认出。车牌能读出大部分字符；人脸能被认识的人认出是谁。
- **辅助指标：按帧召回 ≥ 99.5%**，口径同现在的 vc_eval：只算"须遮住"档的真目标，"尽力"档不算。
- **误打**：只要求不比现在差，不设 99.9%。
- **标准答案**：检测器找候选，多模态模型判定，人工只核分歧并做抽查。
- **测试视频**：由用户提供新的行车视频，人脸要多（路口、商业区、人行横道），不参与任何训练。

### 拆分

本文档只覆盖**子项目 1：测得准**。下面两个子项目等子项目 1 出了真实数字后，各自另走设计流程：
- **子项目 2：按轨迹打码**。确认为真的目标，整条轨迹打码：出现前几帧往前补，中间断几帧也补。
- **子项目 3：模型提升**。用测试集之外的漏检做正例补训，必要时换更大的模型或分块检测。

## 2. 数据流

1. **视频入库**
   - 用户的视频放到 `data/videos/test-v2/`，按每秒 10 帧抽帧到 `data/frames/<段>/`（沿用 vc_extract）。
   - 这些段不进 `vc_train dataset` 的任何 `--stem`。
2. **找全候选**（宁可多、不能漏）
   - 车牌：OWLv2，阈值 0.05，另对画面做 2×2 分块（块间重叠 20%）再检测一遍，专找远处小车牌。
   - 人脸：RetinaFace 阈值 0.2，YuNet 阈值 0.3。
   - 学生 r3：阈值 0.01，经 vc_detect。
   - 所有框按类别取并集，用 `tracks.py` 连成候选目标，写 `data/gt/<段>/tracks.jsonl`。
3. **系统输出**：用当前默认设置（r3 + YuNet + 16 px）跑 vc_redact，得到 `masks.jsonl`。被评测的永远是这份输出；换设置就重跑这一步和第 6 步，前面几步不用重跑。
4. **模型判定**（Codex CLI，沿用 vc_hardneg 的命令判定器、4 张一拼、续跑逻辑；只有设置 `VC_HARDNEG_ALLOW_LLM=1` 才会调用）
   - **问题 A（每个候选目标问一次）**：给 3 张截图（最大的一帧、最清楚的一帧、时间居中的一帧），问"是不是真车牌或真人脸；如果是，最清楚的那张能不能认出"。答案取值：`real_readable` / `real_unreadable` / `not_real` / `unsure`。
   - **问题 B（只问未打码的帧）**：对问题 A 判为真的目标，逐帧检查系统有没有遮住它（遮住的判定同 vc_eval 的覆盖标准）；没遮住的帧逐张问"这一帧能不能认出"。答案取值：`readable` / `unreadable` / `unsure`。
5. **人工核对**：生成本地网页，用户点选后导出 JSON 到下载目录，再导入。
   - **H1 全核**：判为泄露的目标，以及问题 A、B 里所有 `unsure` 的目标。
   - **H2 抽核**：问题 A、B 的模型答案各随机抽 50 个，共 100 个，估计模型出错率。
   - **H3 整帧标注**：每类随机抽 150 帧整帧，共 300 帧。用户把画面里每个看得清的车牌和人脸都框出来，估计"所有检测器都漏掉"的比例。
   - 人工结论覆盖模型结论，沿用 vc_hardneg：同一 id 以最后一条为准，`human` 优先。
6. **出报告**（`vc_eval objects`）：见第 4 节。

## 3. 组件

新建 Python 包 `py/vc_gt`，每个模块一个职责。

| 模块 | 输入 → 输出 | 依赖 |
|---|---|---|
| `tracks.py` | 逐帧的框 → 目标列表。同类贪心匹配：IoU ≥ 0.3，或中心距离 < 1.5 倍框宽；允许中间断 ≤ 3 个抽样帧 | 纯函数 |
| `candidates.py` | 抽好的帧 → `tracks.jsonl`（每个目标：id、类别、逐帧框和来源） | vc_label 的老师（OWLv2 新增分块选项）、vc_detect、`tracks.py` |
| `crops.py` | 目标 + 帧 → 问题 A 的 3 张截图；未打码帧的截图 | OpenCV；锐度用拉普拉斯方差 |
| `judge.py` | 截图 → `judgments.jsonl`（问题 A、B），可中断续跑 | vc_hardneg 的 `CommandJudge`、`judgments.py` |
| `audit.py` | 生成 H1、H2、H3 的网页；导入用户导出的 JSON | vc_hardneg 的复核页（H1、H2）；**新写**整帧画框页（H3） |
| `cli.py` | `python -m vc_gt candidates / judge / review / annotate / import-human` | — |

vc_eval 新增 `objects.py` 和命令 `vc_eval objects --gt data/gt/<段> --masks <masks.jsonl>`，按第 4 节出数字和报告页。

配置文件 `configs/gt.json`：各检测器阈值、分块参数、跟踪参数、截图张数、问题 A 和 B 的提示词、Codex 命令（同 `configs/hardneg.json` 的写法）、抽样数量和随机种子。

## 4. 指标与达标判定

记号：一个目标的"判定结果"取人工结论，没有人工结论时取模型结论。

- **按目标不泄露率** = 1 − 泄露目标数 / 看得清的真目标数。
  - **看得清的真目标**：问题 A 判为 `real_readable` 的目标，或问题 B 有任意一帧判为 `readable` 的目标。
  - **泄露目标**：至少有一帧未打码、且该帧判为 `readable` 的目标。
- **按帧召回**：抽样帧上，判为真、且属于"须遮住"尺寸档的目标框里，被遮住的比例。尺寸档沿用 vc_eval 的 `metrics.must_mask`（按画面高度缩放；1080p 下车牌宽 ≥ 24 px，人脸高 ≥ 12 px）。
- **置信区间**：Clopper-Pearson 精确二项区间，95%。
- **大家一起漏的比例**：H3 里人工框出、却与任何候选目标都对不上（IoU < 0.3）的看得清目标数，除以 H3 里人工框出的看得清目标总数。单独报告，不并入主指标。
  - 如果这个比例的点估计 > 0.1%，报告里标红，并注明主指标会被高估。
- **模型出错率**：H2 里模型答案被人工推翻的比例，分问题 A、问题 B 报告。
- **达标**：某一类同时满足以下四条，才写"达标"；否则只报告数字。
  - 看得清的真目标 ≥ 3,000 个；
  - 按目标不泄露率的点估计 ≥ 99.9%；
  - 按帧召回的点估计 ≥ 99.5%；
  - 大家一起漏的比例点估计 ≤ 0.1%。
- **报告内容**：每个泄露目标的截图（未打码且看得清的帧）、目标数、区间、按段明细。

## 5. 已知局限

- **抽样漏算**：评测按每秒 10 帧抽样，两个抽样帧之间的单帧泄露可能测不到。对已判为泄露的目标，报告会附上前后各 5 个原始帧（不抽样）的打码情况，供人工确认。没被抽到的泄露只能靠子项目 2 的轨迹打码来减少。
- **模型判定有误差**：问题 A、B 由模型判定，误差由 H2 估计。99.9% 的结论成立的前提是 H2 显示模型出错率足够低；如果 H2 推翻比例 > 2%，放量前要先改提示词或判定方式。
- **"看得清"有主观性**：以用户在 H1 里的判断为准。

## 6. 测试与试点

- **单元测试**（只跑相关文件）：
  - `tracks.py`：连接、断帧、换道交叉、类别隔离；
  - `crops.py`：挑帧规则；
  - `judge.py`：用假命令替代 Codex，不联网，验证续跑和人工优先；
  - `objects.py`：泄露定义、按帧召回、区间计算，用手算的小例子核对；
  - `audit.py`：网页生成和 JSON 导入格式。
- **试点**：新视频到位前，先拿 sg_drive_60s（2 分钟）跑通全流程。
  - 人工做一轮小规模 H2：约 50 个问题 A、50 个问题 B。
  - 推翻比例 ≤ 2% 才放量到用户的新视频。
- **放量**：新视频到位后，按段分批处理，每批停下给用户看数字。视频不够 3,000 个目标时，报告写明还差多少。

## 7. 成本与约束

- **计费流量**：每次模型调用都会上传 4 张拼好的截图。每类约 3,000 个目标，问题 A 约 750 次调用，问题 B 视未打码帧的数量而定，预计每类合计 1,000–2,000 次。默认不联网，由 `VC_HARDNEG_ALLOW_LLM=1` 放行。
- **本机负载**：候选检测（OWLv2 分块）是这里面最重的一步，按段在后台跑，不和训练同时跑。
- **人工量**：H1 几十到几百个目标，H2 100 个，H3 300 帧（约 1–2 小时）。

## 8. 补记（2026-10-23，任务 4 实测后）

- **实测**：sg_drive_60s 的 3 帧上，逐车跑 OWLv2 加 2×2 分块，每帧要 11–16 秒（每辆车约 0.5 秒，每帧 20–29 辆车），车牌候选 104–211 个，其中宽 ≥ 24 px 的有 42–92 个；只跑分块每帧约 2 秒，宽 ≥ 24 px 的候选少 10–15%。
- **用户决定**：试点先按原方案找候选（逐车加分块、每秒 10 帧），2 分钟试点在本机后台跑约 4 小时；放量方式等试点数字出来后再定（备选：只跑分块并降到每秒 5 帧，或换有 NVIDIA 显卡的机器跑）。
- **小目标不送模型**：车牌宽度、人脸高度从未达到 `vc_eval.metrics.must_mask` 尺寸的目标，不问问题 A，也不计入任何指标。它们本来就认不出，按目标泄露率不受影响；这样可以省下大部分调用。
