# 按轨迹打码（子项目 2）

日期：2026-10-27。前置：
- `docs/superpowers/specs/2026-10-22-gt-test-set-design.md`（子项目 1，泄露查找器，§12 起改为"找泄露"）；
- `docs/superpowers/specs/2026-10-19-stable-masks-and-speed-design.md` §3（现有补框：`BoxTimeline`）；
- PR warsen-lab/dashcam-anonymizer#3（默认 r3 + `plate_min_width_px` 16）。

## 1. 背景与目标

子项目 1 在 `sg_drive_60s` 上找出了泄露，人工确认的有 3 处，全是车牌：

| 泄露 | 学生模型在关键帧上（10 档，每 6 帧一个关键帧） | 现有规则下为什么漏 |
|---|---|---|
| o16042@1770（保时捷） | 1686–1764 稳定检出（0.46–0.87），1770 和 1776 连续两个关键帧漏检 | 连漏两次，幽灵结束，[1770, 1776) 不打码（`hold_lost_ghosts` 默认关） |
| o19940@2172（同一辆保时捷） | 2166、2172 没检出，2178 才检出（0.50） | "目标第一次被检出之前的帧不打码"（旧实现能往回保持，为了观感在 2026-10-19 §3.5 有意去掉了） |
| o25810@4068（货车） | 3318–4092 整段低分检出（0.05–0.75），断断续续；4062、4068 连续漏检 | 和第一处一样，连漏两次空出一段；4074 重新检出时开始了一条新轨迹 |

另外三处核对时判为不算泄露：o30556@4134、o30920@4158 是 SLOW VEHICLE 警示牌，o22334@2868 框里已经打了码。

**目标：** 已确认的目标按整条轨迹打码：
- 中间断开几个关键帧，就把空档连上；
- 第一次检出之前的几帧，往回补上。

### 用户已定的取舍

- **泄露清零，误打设上限**：上面 3 处必须全部消失；误打和打码面积不能比现状涨太多，上限见 §5，看到数字后用户可以改。
- **窗口延后输出**：仍然只走一遍视频，帧先多缓存几个关键帧再输出，补的长度不超过窗口。不做两遍（先检测、再打码），也不只是打开现有开关。

## 2. 行为

两个新配置键（`configs/redact.json`，`--config` 读取，与其他键同样校验）：

| 键 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `track_lookahead_keyframes` | 5 | 整数 0–30 | 窗口 W：输出比现在再晚 W 个关键帧，空档最多连上 W 个连续漏检的关键帧。0 = 关闭，行为与现在完全一样 |
| `track_backfill_keyframes` | 2 | 整数 0 到 max(0, W − 1) | 往回补 B：要打码的轨迹第一次检出时，往回补最多 B 个关键帧间隔；W = 0 时只能是 0 |

### 2.1 中间断开就连上

- 一条轨迹在关键帧 k_a 最后一次真实检出，之后漏检。它以幽灵的身份最多活 W 个关键帧（现在固定是 1 个）。
- 在 k_b（b − a − 1 ≤ W，即中间最多漏 W 个）重新配上时，[k_a, k_b] 之间整段打码：中心和宽高从 k_a 的检测框线性插值到 k_b 的检测框，按现有规则外扩、平滑。`masks.jsonl` 里这些帧的 `origin` 为 `bridged`。
- 与现在的差别：现在只漏一个关键帧时，是从保持到的位置插值到新框；W ≥ 1 后改为从最后一次真实检出插值到新框。
- 幽灵配对：预测位置 = 最后一次真实检出 + 速度 × 经过的帧数。配对规则沿用 2026-10-19 §3 的两轮配对，包括 §3.8 的"低分配对只走第一轮"。
- 窗口内一直没配上：按现有规则，漏检后的第一个间隔原地保持，然后轨迹结束；`hold_lost_ghosts` 的含义不变。
- **只连已确认的轨迹**：连的是空档之前已经确认要打码的轨迹（高分，或在相邻两个关键帧被真实检出，即现有 §3.4 的规则）。空档两端各有一次低分检出，不算确认，也不连。

### 2.2 出现前往回补

- 一条轨迹一旦确认要打码，就往回补，最多 B 个关键帧间隔：从它第一次真实检出的关键帧 k_a 往前补到 k_{a−B}。高分轨迹在 k_a 当场确认；低分轨迹在 k_{a+1} 确认。往前补的部分不能早于已经输出的帧，所以实际能补多少由窗口决定：高分轨迹最多补 W − 1 个间隔，低分轨迹（晚一个关键帧才确认）最多 W − 2 个。
- 位置：已知速度（确认时已有前两次真实检出）就按速度往回推；不知道就原地。每个间隔每轴的位移不超过半个框宽 / 框高，与现有保持的上限一样。框大小取第一次检出的框。`origin` 为 `backfilled`。
- 不在视频开头之前补。

### 2.3 防误打

- 补出来的框（连上的、往回补的）都不是检出：
  - 不写进 `detections.jsonl`；
  - 不参与确认；
  - 不更新速度（速度只从真实检出量）。
- 单次的低分误检：没确认，所以不会被连上，也不会触发往回补，与现在一样不打码。
- 已确认的误检会多留码：连上的空档最长 W 个间隔，往回补最长 B 个间隔。§5 量这部分代价。

### 2.4 输出

- `masks.jsonl` 的 `origin` 增加 `bridged` 和 `backfilled` 两个值；`detected`、`interpolated`、`held` 不变。
- `stats.json` 增加：
  - `lookahead_keyframes`、`backfill_keyframes`（实际用的值）；
  - `bridged_mask_boxes`、`backfilled_mask_boxes`（两种补框各有多少个打码框）；
  - `buffered_frames_peak`（缓存帧数的峰值）。
- 运行结束的统计行加一句"bridged N, backfilled M"。

## 3. 结构

### 3.1 新单元：关键帧连接器（`cpp/src/track/keyframe_linker.{h,cpp}`）

- **输入**：按顺序送入的关键帧（`Keyframe`：时间和检测框）。
- **输出**：晚 W 个关键帧吐出的"已连好的关键帧"。每个框带三样东西：
  - 轨迹号；
  - 来源：真实 / 连上 / 往回补；
  - 是否打码（已确认）。
- **职责**：配对（两轮规则，从 `BoxTimeline::match` 原样搬出，`BoxTimeline` 不再自己配对）、幽灵寿命、确认、连上、往回补、速度。
- **W = 0 时**：吐出顺序与时机和现在完全一样，配对与确认结果也一样。

### 3.2 `BoxTimeline` 的改动

- 不再配对、不再确认：按连接器给的轨迹号，把相邻关键帧上同号的框连起来。
- 插值、原地保持、尺寸平滑、面积上限、外扩、`hold_lost_ghosts`：逻辑不动，只是输入换成带轨迹号的框。
- 连上 / 往回补的框按 `origin` 记录；外扩和平滑与插值帧一样处理。

### 3.3 `vc_redact` 的改动

- `redact_job` 的帧缓存从"上一个关键帧到当前关键帧"加长到 W + 1 个间隔。帧都在内存里（`pipeline` 为 `cpu-frames`），1080p 4:2:0 每帧约 3 MB；60 fps、W = 5 时约 36 帧，约 110 MB。
- 现有的"缓存满 `kMaxBufferedFrames`（120）帧就强制一个关键帧"按间隔算，不变。所以极高帧率时缓存上限是 (W + 1) × 120 帧。启动时按画面大小估算缓存峰值，超过 2 GB 时报错并提示调小 W。
- `detections.jsonl` 仍在关键帧检测完、确认结论出来时写（W = 0 时与现在一致；W > 0 时 `confirmed` 字段按连接器的结论写，可能晚几个关键帧才落盘）。

## 4. 测试

- **连接器单元测试**（GoogleTest，`cpp/tests/keyframe_linker_test.cpp`）：
  - W = 0 与现有 `BoxTimeline` 配对、确认结果一致（沿用现有用例的输入）；
  - 连上：漏 1、2、W 个关键帧后重新配上，整段有框；漏 W + 1 个就不连；
  - 未确认的轨迹不连；两端各一次低分不连；
  - 往回补：高分当场补；低分确认后补；按速度往回推且位移封顶；补不到已输出的帧；不补到视频开头之前；
  - 视频结尾：窗口内的关键帧全部吐出，幽灵按现有规则收尾。
- **`BoxTimeline` 测试**：现有用例改为通过连接器（W = 0）喂入，期望不变；新增 `bridged` / `backfilled` 的 `origin` 和外扩用例。
- **`redact_job` / `redact_config` 测试**：新键的解析与范围；缓存加长后输出帧数与顺序不变；stats 字段。
- **回归**：用 W = 0、B = 0 重跑 `sg_drive_60s`，`masks.jsonl` 与改动前逐行一致。
- 只跑与改动相关的测试目标（本机禁止全量），全量交给 CI 或用户指定的机器。

## 5. 验收

**基线**：`data/reports/fp-r3-pw16`（r3 + YuNet，10 档，`plate_min_width_px` 16，三个留出段 `sg_drive_60s` / `sg_drive_1200s` / `sg_drive_2400s`），同一台机器、同一时段重跑一遍作对照。

1. **泄露（硬门槛）**：
   - 用新默认值重跑 `sg_drive_60s`，抽出打码后的帧；
   - 跑 `vc_eval objects`，已确认的 3 处泄露必须全部消失。
   - 打码变了，会出现问题 B 还没判过的"须遮住尺寸的未打码帧"。先数出要发多少组，用户同意后再调用模型；判为"能认出"或"拿不准"的帧照旧做核对页给用户核。新确认的泄露要在验收报告里逐个说明原因。
2. **召回（硬门槛）**：三段合计，车牌、人脸的 P1 覆盖率不低于基线（车牌 98.2%，人脸 100%）。
3. **误打与观感（上限，用户看到数字后可改）**，三段合计，相对基线：
   - 误打面积（对不上老师框的打码）均值、95 分位：各涨不超过 10%；
   - 屏上面积均值、99 分位：各涨不超过 10%；
   - 帧间跳变：不超过基线 + 0.5 个百分点。
4. **速度（只报告）**：`sg_drive_2400s` 上的吞吐与基线对比。
5. **调参**：先按默认值（W = 5，B = 2）跑。若泄露未清零或超了上限，在 W ∈ {3, 5, 8}、B ∈ {1, 2, 3} 里找满足 1–3 的组合；都不满足就停下来，把各组合的数字给用户定。
6. **报告**：`docs/reports/track-masking-2026-10-27.md`，附连上 / 往回补的抽样拼图。

## 6. 不在本设计范围内

- 关键帧之间的视觉跟踪（光流、KCF 等）：窗口内只做插值。
- 两遍处理和整段视频级的轨迹连接。
- 换模型、改检测阈值（子项目 3）。
- 人脸的泄露：`sg_drive_60s` 上没有找到，本子项目的改动同样作用于人脸，但验收只看 §5 的召回与误打。

## 7. 实施时的修正（2026-10-27，写计划时）

- **§3.2 的结构**：`BoxTimeline` 的配对没有删掉，而是搬进 `track/box_matching`，由连接器和 `BoxTimeline` 共用。`BoxTimeline` 加 `linked` 模式：W ≥ 1 时按连接器的轨迹号连框、按 `BoxLink::masked` 打码；W = 0 时完全照旧，自己配对和确认。外面再包一层 `TrackMasker`，`vc_redact` 只和它打交道。这样 W = 0 不改动任何既有路径，原有 69 个 `BoxTimeline` 测试一行不改。
- **§2.2 往回补的上限**：连接器在处理完新关键帧之后才吐出最老的一个，所以确认时 k_{a−B} 一定还在窗口里。高分轨迹在 k_a 确认，低分轨迹在 k_{a+1} 确认，都能补满 `track_backfill_keyframes` ≤ W − 1 个，只有视频开头会少补。§2.2 里"高分最多 W − 1、低分最多 W − 2"作废。
- **§5 的基线**：召回、误打面积和观感直接用已有报告 `data/reports/fp-r3-pw16` 的数字作对照，不再同一时段重跑一遍三段视频，省下约 20 分钟的重负载；速度对照只在 `sg_drive_2400s` 上用 W = 0 和默认值各跑一次 `vc_redact`。`vc_eval falsepos` 数的是检测框，补出来的框不算检测，所以不用它衡量误打，改看 `vc_eval run` 报告里的"误打面积"。

## 8. 试跑后的调整（2026-10-27，用户决定）

**试跑**（`sg_drive_60s`，与基线 r3 + 16 px 对比；误打面积 = 对不上老师框的打码占画面的比例）：

| 参数 | 剩下的泄露 | 误打面积均值 | 误打面积 p95 | 屏上面积均值 |
|---|---|---|---|---|
| 基线 | 3 | 0.517% | 1.227% | 0.79% |
| W = 2, B = 1 | 1（o16042） | 0.580%（+12%） | 1.330%（+8%） | 0.88% |
| W = 2, B = 1 + hold_lost_min_score 0.5（默认） | 0 | 0.590%（+14%） | 1.363%（+11%） | 0.91% |
| W = 5, B = 2 | 1（o16042） | 0.684%（+32%） | 1.581%（+29%） | 1.01% |
| W = 5, B = 2 + `hold_lost_ghosts` | 0 | 0.726%（+40%） | 1.658%（+35%） | 1.08% |

o16042@1770 补不上：保时捷开到画面底边被截掉一半，学生模型在 1764 之后再没检出它，窗口里没有可连的重新检出。全局打开 `hold_lost_ghosts` 能盖住，但误打面积涨 40%。

**决定**：
- 默认值改为 `track_lookahead_keyframes` 2、`track_backfill_keyframes` 1。
- 新键 `hold_lost_min_score`（默认 0.5，[0, 1] 内的数，或 null 关闭）：已确认的轨迹丢失后，若它**真实检出**里的最高分不低于这个值，就像 `hold_lost_ghosts` 那样再保持一个间隔（在保持到的位置，不再移动，`origin` 为 `held`），然后结束；视频结尾的幽灵同样处理。补出来的框（`bridged` / `backfilled`）的分数不算。`hold_lost_ghosts` 为 true 时照旧对所有已确认轨迹生效，两个键是"或"的关系。`BoxTimeline` 的 `TimelineConfig` 里默认关闭，只有 vc_redact 的配置默认打开。
- 按 W = 0 回归时，要同时把 `track_backfill_keyframes` 设为 0、`hold_lost_min_score` 设为 null，输出才与改动前逐字节一致。
- §5 的验收照旧，在三段视频上看误打与召回；数字出来后由用户决定是否接受。
